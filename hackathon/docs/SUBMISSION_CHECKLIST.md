# Submission checklist

The [judge guide](JUDGES_GUIDE.md) is the product entry point. The [evidence index](../evidence/README.md) separates current checks from retained historical material.

## Repository and presentation

- [x] Current public branch and its CI checks verified after the final changes.
- [x] Live app and health endpoint open without a private account.
- [ ] Render serves the audited source commit and the updated live primary-model workflow is verified.
- [x] Latest video appears immediately below the README live-app link and plays publicly.
- [x] Video runtime is at most three minutes; the current export is 2:55.817 and 33,132,466 bytes.
- [x] Current eight-screen workflow, source quantities, model roles and calculation boundaries agree across documentation.
- [x] Tests exercise current UI and real server transitions; retired UI checks are explicitly historical.
- [x] Secrets scan passes; no provider credentials, private state, local profile paths or audit backups are published.
- [x] License and third-party notices are available; retained contribution history remains intact.

## Submission form and human declarations

- [ ] Authorized Representative confirms team members, rights, new-work eligibility and the actual track/award controls.
- [ ] Required descriptions, Meta usage, partner feedback and other form fields reflect actual behavior and model availability.
- [ ] Public GitHub, live app and accessible video URLs are entered correctly.
- [ ] Representative submits the entry, saves the receipt and reopens it to verify stored values.
- [ ] Public source and video remain available through judging.

The official participant guide requests a three-minute demonstration and an accessible video URL. The inspected form uses a video URL field, not a local MP4 upload, and states no MP4 megabyte limit. Do not invent a size cap or mark personal declarations complete from automated checks. A browser-emulated mobile test is not a physical-phone test.
