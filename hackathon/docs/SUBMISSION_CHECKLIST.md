# The Meta Hackathon build — submission checklist

The recovery-room proof is collected in [current evidence](../evidence/README.md). Complete these owner gates against the independently audited candidate.

- [ ] Review the complete uncommitted diff, source manifest and contributions; resolve findings and repeat affected verification.
- [ ] Select the intended public candidate branch and authorize integration/publication separately.
- [ ] Run the guide on a physical phone: open the recovery room, route selection, source inspection, typed acceptance, shock, renewed decision and export.
- [ ] Re-run provider pre-flight. Present Wonder and a GREEN Spark Open route; check the selected route in the room. Choose an alternative explicitly when a route is RED.
- [ ] Verify all human contributors, Representative, rights, proprietary license, new-work eligibility, account credits and actual track/bonus form controls.
- [ ] Film the [eight-shot path](DEMO_RUNBOOK.md) with human narration. Retain original takes, actual model identities and observed inference durations.
- [ ] Edit exactly 180 seconds, retime [captions](CAPTIONS_DRAFT.srt), create the thumbnail and complete [video QA](VIDEO_QA.md).
- [ ] Upload approved media. Open source/video links signed out and verify the approved candidate, access and full playback.
- [ ] Reconcile [submission text](SUBMISSION_DRAFT.md) with actual field limits, contributor declarations and attached evidence.
- [ ] Submit as the authorized Representative, save the receipt, reopen the stored entry and verify every value and link.
- [ ] Keep the approved source and video available through judging.

Protect operator/provider credentials and export passphrases throughout recording. Export encrypted packets with a separate passphrase; retain independent checkpoints in separate trusted storage. [Run guide](../RUN_GUIDE.md) contains exact local commands.
