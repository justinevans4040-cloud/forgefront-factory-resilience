# Current interface design system

The authoritative tokens are in `public/ui/theme.css`; the browser shell is `public/ui/kit.mjs`. Earlier Muse Wonder design critiques and their original scores are retained as historical records. They do not certify the current interface or establish a new live review.

## Visual language

The workspace uses charcoal surfaces, silver text, fine borders and restrained action emphasis. Amber marks held/starved work; warm red identifies offline or unavailable conditions. Status always includes a text label, so meaning is not carried by color alone. The ForgeFront logo retains its source colors.

The header holds identity, command search, The Britt status and restore controls. Eight named steps lead through Incident, Findings, Decision, The Britt plan, Disrupt, Evidence, Shop and Settings. Panels use plain headlines, tabular quantities, source-linked records and consistent action placement.

## Data and actions

Quantities come from the current API snapshot. Missing time or cost remains pending; a constrained option never appears as a zero-hour successful recovery. Recovery allocations come from the server engine. Previewing an outage and applying it are distinct actions. Human authorization and task approval remain deliberate and visibly separate from model drafting.

## Accessibility and motion

Controls use semantic buttons, labels and visible focus. Responsive layouts retain access to every named step and complete source details. `prefers-reduced-motion` removes unnecessary animation while preserving state labels. Current browser verification checks the actual UI, keyboard actions, desktop/mobile bounds and console errors; historical SVG geometry checks are not credited as current coverage.
